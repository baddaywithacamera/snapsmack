The Current Situation

This is Alpha software. It runs real sites — Sean runs several of them on it every day, which means he finds out about breakage before you do. Things do occasionally break. When they do, fixes are fast because the person who broke it is also the person who fixes it, and he has skin in the game.

If your site is down, work through the list below before filing a report. Most problems are self-diagnosable and fixable in under five minutes.

Known Issues

Photo editor on mobile. The canvas-based photo editor works on mobile but the touch targets are too small and handle dragging is awkward. This is a known limitation — SnapSmack is a desktop-first product and the editor reflects that. A mobile-optimised version is planned but not prioritised for Alpha.

Cloud backup status reporting. In Smack Up Your Backup, after a large upload completes the status indicator sometimes doesn't update to reflect success. The backup itself completes correctly. Check the session log in your backup directory for ground truth on what actually happened.

Skin gallery development placeholders. Skins marked as development status show as empty cards in the gallery. They're in the repo but not available to install yet. This is intentional and will resolve as skins reach stable status before Beta.

If Your Site Is Down Right Now

White screen or blank admin page. A missing database table is the most common cause after an update. Go to Admin → Boring Ass Stuff → Schema Recovery and run it. It reads the canonical schema and creates any missing tables automatically. Fixes most post-update problems without any manual SQL.

PHP errors on screen. If you're seeing raw PHP error output, that's actually helpful — read it. The error message will tell you exactly what file and line broke. If it's a missing file after an FTP update, you likely missed something in the transfer. If it's a function not found error after a partial update, run the update again cleanly.

Missing thumbnails. Run Rebuild Thumbnails from the admin tools page. If the thumbs directory doesn't exist, create it and make it writable by the web server (chmod 755 or 775 depending on your host).

500 errors. Check your server error log — Apache's error.log or PHP's error log depending on your setup. The actual error is always in there. If it's a permissions problem, the fix is usually chmod. If it's something in the code, file a report.

Everything else. Tell Sean. Include your PHP version, MySQL version, the error message if there is one, and what you were doing when it broke. Screenshots are fine. Stack traces from the error log are better.
