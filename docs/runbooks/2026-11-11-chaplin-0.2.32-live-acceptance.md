> Verification-only runbook. Sean builds, signs, publishes, deploys, supplies credentials/2FA, and makes release decisions. This document does not authorize deployment or registry changes.

## 1. Preflight and identity

The source manifest on `dev` declares CHAPLIN **0.2.32**. Before live acceptance, the published skin registry and the installed site must also report 0.2.32.

```powershell
$registry = Invoke-RestMethod -Uri 'https://snapsmack.ca/releases/skins/registry.json'
$chaplin = $registry.skins.chaplin
$chaplin | Select-Object name, version, download_url, download_size, signature | Format-List
if ($chaplin.version -ne '0.2.32') { throw "STOP: registry offers CHAPLIN $($chaplin.version), not 0.2.32" }
if ([string]::IsNullOrWhiteSpace($chaplin.signature)) { throw 'STOP: registry has no CHAPLIN signature' }
```

Record the registry output, UTC time, target site, installed version, and the updater's signature-verification result. Use the normal authenticated skin installer only after Sean has published the owner-built package.

**STOP** before visual testing if the registry, package, or installed version is not exactly 0.2.32; the signature is absent or rejected; SMACKBACK reports an unexplained warning; or the target site's before-state was not captured.

## 2. Supported viewports and evidence

Test only the supported desktop/large-tablet widths: **1920, 1440, and 1024 CSS pixels**. Phone widths are not acceptance criteria for CHAPLIN.

At each width, use a fresh browser load with the cache disabled and capture full-page screenshots of:

- landing/home;
- a single photo page with title, date, and description;
- archive in square mode;
- archive in masonry mode;
- a text/info page;
- the bottom of every tested page showing the footer.

Record the URL, viewport, browser, UTC time, page type, control state, and screenshot filename. Preserve the browser console output if it contains an error.

## 3. Complete archive-control path

Use two visibly different values for each applicable global Archive Appearance control, one state at a time:

1. Save **COLUMNS**, reload the admin page, and confirm the stored value is shown.
2. Load a fresh public archive and confirm the visible column count changes at 1920, 1440, and 1024 without forcing sparse tablet columns wider than the available photographs.
3. Repeat save → admin reload → fresh public archive for **THUMBNAIL SIZE**.
4. Repeat for archive layout (**square** and **masonry**) and any other archive control exposed by this installed build.
5. Scroll through the full archive. It must continue loading; a page-one-only result or visible pagination is a failure.

Do not count injected settings or HTML inspection as visual proof. Evidence must show the saved control, fresh admin reload, and rendered public result.

## 4. Visual acceptance checks

At all three widths, mark PASS only when the screenshots show:

- no horizontal page overflow, clipped photographs, overlapping frame ornaments, or unreadable text;
- the owner-selected archive columns and thumbnail size visibly honored;
- square and masonry archives preserving photo orientation and stable gaps;
- sparse archives at 1024 using available columns without stretching a few items into an unintended layout;
- landing, photo, archive, and text pages retaining CHAPLIN's frame/rule/ornament geometry;
- one footer with its intended small type, reduced band height, and air above it—no doubled gap or duplicate footer;
- no missing controls, broken images, PHP warning, browser console error, or new SMACKBACK warning.

Use this evidence table:

| Width | Page/control state | Result | Evidence |
|---:|---|---|---|
| 1920 | landing, photo, archive square/masonry, text, footer | PASS / FAIL / NOT CHECKED | screenshot/log names |
| 1440 | landing, photo, archive square/masonry, text, footer | PASS / FAIL / NOT CHECKED | screenshot/log names |
| 1024 | landing, photo, archive square/masonry, text, footer | PASS / FAIL / NOT CHECKED | screenshot/log names |
| all | admin save → stored reload → fresh rendered effect | PASS / FAIL / NOT CHECKED | before/after captures |

## 5. Stop and recovery conditions

Stop acceptance and do not approve 0.2.32 if any identity check fails; any supported width clips or overlaps; an archive control does not survive save/reload or has no visible effect; endless scroll stops; the footer remains oversized/duplicated; a PHP or browser error appears; or SMACKBACK changes state unexpectedly.

On failure, save the exact URL, width, control values, screenshot, console output, installed version, and SMACKBACK state. Do not rebuild, republish, re-bless files, change the live database, or try another site to see whether it repeats. Sean chooses rollback or the next corrective action.

Acceptance is complete only when every applicable row is PASS with evidence. Any missing width, page type, control state, or admin-save path remains NOT CHECKED.
